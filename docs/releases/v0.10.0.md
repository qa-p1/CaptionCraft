# CaptionCraft v0.10.0

Build **0.10.0+2006** · Android, iOS, Windows x64

Builds verified. Binary publication remains a draft pending the native
corresponding-source distribution check below. CaptionCraft-owned code is now
GPL-3.0-or-later, including the code in this build.

## Highlights

- Optional first-login setup and Settings for your own Groq, GIPHY, Pexels and
  Pixabay keys, with native-browser signup links.
- No .env, embedded developer credentials, transcription proxy or app-level
  three-run quota. Provider quotas/charges still apply.
- AES-256-GCM cloud key backups, account-scoped secure local storage, recovery
  codes, offline saves, revision conflict handling and confirmed reset.
- Local import, editing, manual captions and export remain usable without keys.
- Windows local editing and runtime-key transcription; keyboard shortcuts,
  timeline navigation, work-area controls and save-before-close behavior.
- Improved Instagram public-payload parsing/fallbacks, strict input validation,
  bounded requests, cancellation/cleanup and actionable blocked-access errors.
- Safer media downloads, recoverable Firebase startup and better logo padding
  across platform icons/launch assets.

Public downloads will appear after distribution checks. An Android update must
match the installed app's signing certificate. Back up important projects/media
and do not uninstall merely to bypass a signature mismatch. Windows has no
cloud login: keys and projects stay on that PC. The ZIP is unsigned and is not
an installer. Do not disable security protections to run an unfamiliar file.

Use **Settings → Connected services** for optional APIs. Keep your recovery code
in a password manager. [Full setup guide](../connected-services.md).

## Known limitations

- Instagram may block anonymous access to public media. Private/deleted/login-only
  content is not promised downloadable.
- Signed-in device recovery, Firebase App Check/OAuth, interrupted downloads/exports,
  low storage, background/resume and large projects still need device QA.
- Physical-device icon inspection and App Store/Play metadata/privacy review remain.
- Apple signing is not complete; the IPA is unsigned.
- Test clean Windows 10/11 x64 machines, runtime prerequisites, codec support,
  long exports, antivirus reputation and accessibility.
- The pinned Windows FFmpeg bundle has a documented relocation workaround that
  disables ASLR on affected codec DLLs. A passed startup test does not make it
  hardened or store-ready.
