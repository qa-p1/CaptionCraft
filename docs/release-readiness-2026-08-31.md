# CaptionCraft release-readiness audit

Base: `origin/master` at `32ebd5d1d7f68d93804659a7832906aa659fadf1`.

## Fixed in code

- Instagram inspection now validates canonical HTTPS post/Reel URLs, uses bounded canonical and public-embed attempts, understands Open Graph, current serialized URL names, and `video_versions` payloads, deduplicates media, and refreshes expiring links on retry. Login/private/error pages are classified before URL extraction so their branding or promotional assets cannot be mistaken for post media.
- Instagram failures distinguish invalid links, private/login-only media, upstream anonymous-access blocking, deleted/unavailable posts, rate limiting, network errors, and timeouts. In-flight requests are cancelled and owned HTTP resources are closed on disposal.
- Instagram CDN downloads now send the required page origin/referer context, have a bounded connection setup, validate the downloaded payload independently of its extension, remove partial files, and give retry-specific messages for expired CDN URLs.
- Firebase initialization failures no longer terminate before Flutter can render. The app presents a sanitized startup failure screen while detailed diagnostics remain in development logs.
- App icon geometry now has optical safe-zone padding. Android adaptive foreground scaling, legacy/round launcher PNGs, iOS icon sizes, and Android/iOS launch images use the same centered mark. Regression coverage checks required PNG dimensions and visible margins.
- Generated golden-test failure images are no longer tracked. The validation workflow now runs for release-readiness branches and includes Android debug packaging after analysis and tests.
- Windows now has a native runner, local-only startup when no Windows Firebase application is configured, Media Foundation playback, FFmpeg export support, disk-space checks, and a release artifact workflow. The generated Windows plugin registrant is tracked so clean clones receive the same plugin graph. The native close button waits for editor persistence and active-render cancellation; a second close presents an explicit force-close warning if storage or rendering is stuck. Initial and minimum window sizes are clamped to the active monitor work area for high-DPI laptops, and the project supplies the compatibility floor required to consume Firebase C++ on CMake 4. The embedded Discover browser is disabled with an explicit explanation on Windows because the stable webview dependency does not provide a production Windows engine.
- The desktop editor now supports conventional non-destructive shortcuts for undo/redo, save, export, import, select all, split, transport control, frame stepping, adjacent-edit navigation, clip nudging, work-area bounds, snapping, delete, markers, fullscreen, and help. Text fields keep ownership of keystrokes, held keys repeat only navigation/nudge actions, and transport requests are acknowledged through state rather than stale callbacks.
- Editor navigation now waits for an atomic local snapshot and stays open on disk/full-access failure unless the user explicitly chooses to discard. The same barrier covers Windows native close, background/hidden lifecycle changes flush locally, opening another project clears stale playback state, and reversed work-area markers replace the stale opposite boundary instead of leaving an invalid range.
- Network-backed timeline inputs reject unsafe redirects, HTTPS downgrades, HTML/error payloads, oversized responses, and stalled transfers; cancellation closes owned clients and removes partial files. Discover, Instagram, Pexels, Pixabay, and element-library services now have explicit ownership/disposal behavior so closing or switching providers does not leak sockets or accept stale results.
- Production transcription configuration now requires an authenticated proxy URL instead of embedding a Groq secret in release artifacts. Firebase App Check uses the current provider API, startup remains recoverable, and the sample environment documents the release configuration boundary.
- Android no longer requests legacy storage behavior on Android 10; the obsolete permission is limited to Android 9 and earlier. Dependency licenses are reachable from both account and Windows local-mode screens.
- Device-quota Firestore rules now bind reads and updates to the authenticated owner, constrain mutable fields, preserve `created_at`, and reject list/delete access. Contract coverage prevents a later broad rule from silently reopening quota documents.
- The iOS target now includes the production App Attest entitlement in Debug, Profile, and Release configurations. Firebase-console provider registration, signing capability/provisioning, and real-device attestation remain external gates.
- Release-readiness branch pushes now run the signed Android, unsigned iOS, and Windows x64 packaging workflows; they remain manually dispatchable after the workflow files reach the default branch. Flutter versions and third-party Actions are pinned to immutable revisions, workflows refuse to build when required production configuration is absent, and signing material is removed from the Android runner even after failure. Android verifies the AAB cryptographically without treating an expected self-signed upload certificate as an error and verifies each APK with `apksigner`.
- The Windows workflow independently downloads the exact Firebase C++ 13.4.0 and FFmpegKit 8.1.2 Full-GPL archives, verifies the Firebase size plus both pinned SHA-256 checksums and SDK identities before CMake can consume them, checks the native runtime and Flutter AOT bundle, launches the packaged executable as a startup smoke test, and publishes a ZIP with build provenance and a SHA-256 checksum. Stock-media and asset-manifest configuration is injected from GitHub Actions rather than a tracked environment file.

## Automated verification

The validation workflow pins Flutter 3.41.2 and Ubuntu 24.04, restores the lockfile, enforces Dart formatting, runs `flutter analyze`, runs the full `flutter test` suite with FFmpeg installed, and builds a debug Android APK. Targeted regression tests cover Instagram fallback parsing and failure classification, request timeouts/disposal, real Windows local-library startup, awaited route/native-close saves, service ownership, Firestore rules, iOS entitlements, pinned Windows inputs/CMake compatibility, icon margins, platform asset completeness, Windows browser fallback, keyboard mappings/repeat behavior, and playback transport request lifecycle. Failed golden images are retained as CI artifacts for diagnosis instead of being committed or ignored.

## Required release gates outside unit tests

- Test a public photo post, carousel, video post, and Reel on real Android and iOS devices from at least two networks. Instagram can block anonymous clients even for public content; no client-only scraper can guarantee access when Instagram returns an error shell. Confirm the UI reports that state rather than presenting it as a private/deleted post.
- Inspect adaptive, round, legacy, iOS, and splash artwork on physical devices and store-preview tooling. Platform launchers apply masks that cannot be reproduced exactly by PNG checks.
- Supply and verify Android release signing, Apple signing/provisioning, production bundle identifiers, App Store/Play metadata, and store privacy declarations. At audit time the repository has no `ANDROID_KEYSTORE_*` Actions secrets, so signed Android packaging correctly stops before building.
- Verify Firebase Auth providers, Firestore rules/indexes, App Check enforcement, OAuth fingerprints/redirect schemes, quotas, and production project selection in the Firebase and Google consoles. Register the iOS App Attest provider/capability before enforcing it.
- Exercise background/resume during downloads, saves, and exports; interrupted exports; corrupted/missing source media; low-storage behavior; very large projects; and long multi-layer exports on representative low-, mid-, and high-end devices.
- Configure the authenticated `CAPTIONCRAFT_TRANSCRIPTION_PROXY_URL` repository variable. It is currently absent, so iOS/Android production configuration correctly fails closed; Windows remains honestly local-only. Stock-media secrets and the asset-pack manifest variable are present, but values were not exposed during this audit.
- Treat `GIPHY_API_KEY`, `PEXELS_API_KEY`, and `PIXABAY_API_KEY` as public-client configuration even when GitHub Actions stores them as secrets: Dart defines can be extracted from a shipped binary. Apply provider-supported origin/app restrictions and quota alerts, monitor abuse, and proxy any credential whose provider requires it to remain confidential. Actions secrets protect CI logs; they do not make an embedded client value private.
- Decide and document the distribution model for the bundled FFmpeg build before publishing. The selected Full-GPL variant includes GPL codecs such as x264/x265 and is effectively GPL v3; the repository currently has no top-level distribution license, third-party notices, or corresponding-source/source-offer process. Legal compatibility and the required notices/source delivery are therefore a release blocker, not an LGPL-only checkbox.
- Create and configure a Windows Firebase application before enabling cloud accounts or AI transcription on Windows. Until then, Windows intentionally remains local-only; this avoids pretending that mobile Firebase files configure desktop securely.
- Replace or rebuild the current MinGW FFmpegKit Windows bundle before calling the ZIP store-ready: its package CMake workaround rebases the codec DLLs and disables `DYNAMICBASE`/high-entropy ASLR to avoid pseudo-relocation failures. The checksum-pinned CI input prevents silent binary replacement, but it does not remove that exploit-mitigation gap.
- Validate the Windows ZIP on clean Windows 10 and 11 x64 machines, including WebView absence messaging, imported codec coverage, hardware acceleration, long exports, low disk space, antivirus reputation, Microsoft Visual C++ runtime availability, installer/uninstaller behavior, Authenticode signing, and accessibility shortcuts. The CI ZIP is an unsigned portable release candidate, not a signed installer.
- Generate and commit `ios/Podfile.lock` from a successful pinned macOS build before final submission; it cannot be resolved faithfully on this Windows host. Review the currently outdated dependency set as a deliberate upgrade project rather than silently taking major-version changes during release hardening.
- Protect the default branch and require validation checks before merge. Repository rulesets, Dependabot/security updates, secret scanning/push protection, and code scanning are repository-owner settings and were disabled or absent during this audit.
